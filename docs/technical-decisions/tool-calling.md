# OpenAI Tool Calling 기술 검증

## 검증 배경

Agent가 사용자의 자연어 요청에 따라 외부 기능을 선택하고 실행하기 위해
Tool Calling이 실제로 어떤 실행 구조를 가지는지 확인한다.

단순 API 사용법을 확인하는 것이 아니라,
향후 Agent Backend에서 LLM과 Tool 실행 계층의 책임을 어떻게 분리할지 결정하는 것을 목적으로 한다.

## 검증할 질문

1. LLM은 자연어 요청에서 적절한 Tool을 선택할 수 있는가?
2. Tool의 arguments는 어떤 형태로 반환되는가?
3. 여러 Tool이 필요한 경우 호출 흐름은 어떻게 구성되는가?
4. Tool이 필요하지 않은 요청은 어떻게 처리되는가?
5. Tool 입력이 잘못됐거나 실행에 실패하면 어떤 처리가 필요한가?
6. Tool 실행 책임은 Agent 구조에서 어느 계층이 가져야 하는가?

## 최소 실험

테스트 Tool

- get_customer
- get_consultations

테스트 케이스

- 단일 Tool 필요
- 여러 Tool 필요
- Tool 불필요
- 존재하지 않는 데이터 조회
- 잘못된 입력

## 관찰 결과

- 자연어 요청에 따라 모델이 필요한 Tool과 arguments를 반환하는 것을 확인했다.
- Tool은 모델이 직접 실행하지 않으며, 실제 실행은 애플리케이션이 담당한다.
- Tool arguments는 JSON 문자열로 반환되어 애플리케이션에서 파싱이 필요하다.
- Tool 실행 결과는 `call_id`를 이용해 기존 Tool 호출과 연결하여 모델에 다시 전달한다.
- 고객 이름만 제공된 요청에서 모델은 먼저 `get_customer`를 호출하고,
  반환된 `customer_id`를 이용해 `get_consultations`를 추가 호출했다.
- Tool 호출 순서를 Backend에 하드코딩하지 않아도 앞선 Tool의 결과를 바탕으로
  모델이 다음 Tool을 선택할 수 있음을 확인했다.
- 모델이 더 이상 `function_call`을 반환하지 않을 때까지
  Tool 실행과 LLM 호출을 반복하면 다단계 Tool Calling을 처리할 수 있었다.
- Tool이 필요하지 않은 일반 요청에서는 `function_call` 없이 바로 최종 응답을 반환했으며,
  동일한 실행 Loop에서 Tool 사용 요청과 비사용 요청을 모두 처리할 수 있음을 확인했다.

## 발견한 문제

처음에는 Tool을 한 번 실행한 뒤 모델이 최종 응답을 반환할 것으로 가정했다.

하지만 고객 정보 조회 결과가 상담 이력 조회의 입력으로 필요한 요청에서는
첫 번째 Tool 실행 이후 모델이 최종 응답이 아닌 추가 `function_call`을 반환했다.

따라서 Tool 호출 횟수와 순서를 미리 정해두는 방식으로는
여러 단계가 필요한 업무 요청을 일반적으로 처리하기 어렵다는 것을 확인했다.
